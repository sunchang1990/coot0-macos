## The gate that keeps every scripted menu dead today

`python/coot_load_modules.py` only appends the GUI script list (`coot_gui.py`, `extensions.py`, `coot_toolbuttons.py`, `gui_*.py`, `enhanced_ligand.py`, `acedrg_link.py`, ...) when `use_gui_qm` is true **and** `import pygtk; import gtk` succeeds. `use_gui_qm` is set in `src/coot-setup-python.cc` only under `#ifdef USE_PYGTK`.

## C++ hand-off points (src/coot_pythonmodule.cc, `#ifdef USE_PYGTK`)

- Module `coot_python` with four functions returning a GtkWidget as a PyGObject: `main_menubar()`, `main_statusbar()`, `main_toolbar()`, `main_hbox()`. Scripts use `main_menubar()` (menus), `main_toolbar()` (toolbar buttons incl. Sphere Refine), the others are exported but unused.
- `USE_PYGTK` also selects Python GUI entry points in C++ when `USE_GUILE_GTK` is not defined: `do_smiles_gui()` -> `smiles_gui()`, `post_ligand_fit_gui()`, `run_clear_backups_py()` at exit (c-interface-build.cc, c-interface-ligands.cc, c-interface-gui.cc).
- Nothing else passes widgets between C++ and Python (no other `pygobject` references).

## Notes on GTK 2.24 symbols

Symbol check with `nm` of 64 functions the scripts rely on, over libgtk, libgdk, libglib, libgobject and libpango: all present except two.
- `gdk_pixbuf_new_from_file_at_size` is not in those libraries; it is exported by `libgdk_pixbuf-2.0.0.dylib` (verified separately), so it is available.
- `gtk_widget_set_flags` does not exist anywhere (it was a macro in 2.x): `set_flags(gtk.CAN_DEFAULT)` is mapped to `gtk_widget_set_can_default`.
Deprecated calls confirmed present: `gtk_widget_set_usize`, `gtk_file_selection_new`, `gdk_font_load`, `gtk_tooltips_*`, `gdk_draw_*`, `gdk_draw_rgb_image`, `gtk_combo_box_*_text`.
Python-2-only idioms are already gone (patch 0007), so the layer targets Python 3 (str, not bytes: C strings are decoded/encoded as UTF-8).
